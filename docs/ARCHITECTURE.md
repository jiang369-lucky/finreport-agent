# 架构与实现取舍

## 数据流

用户问题 → 恢复本会话近期问答与早期摘要 → 选择任务模板 → LangGraph 模型/工具循环 → 官方 MCP Client → 官方 MCP Server → 中文财报证据与 Decimal 计算 → 引用检查 → 保存会话、归档和运行记录。

模型只输出工具名与结构化参数。执行器逐项做 Pydantic 校验。日期边界在配置、导入、工具和数据库查询四处生效。工具不能获取任意文件、执行任意 SQL 或执行模型生成的代码。

## 哪些做得深入

1. 证据：PDF 物理页码、原始 URL、披露日、文件哈希、按页原文与单元格行。引用可回查；候选数字不得直接当作已核验事实。
2. Harness：模型循环、参数校验、工具白名单、轮次/调用/超时预算、有限重试、引用修复、失败与中断持久化。
3. 上下文：最近最多四轮完整问答加有长度上限的早期摘要；摘要不替代原始证据。
4. 短期记忆：本会话任务状态、研究公司、完整历史与近期窗口；会话之间隔离。

## 哪些保持轻量

1. 会话摘要：按原始问答生成轻量关键摘录，保留最初问题和较近早期要点；保存到 PostgreSQL。没有独立长期记忆、向量召回工具。
2. 任务模板：事实查询、指标比较和现金流分析三个提示模板加确定性路由，统一称为任务模板。
3. 前端：原生 HTML/CSS/JS，提供真实资料、会话、证据、过程和会话摘要查看。没有外部 CDN 或前端构建链。
4. 检索：中文 BM25、查询套话清理、公司/报告期过滤、主要财务数据页排序、模型多轮改写。当前没有另外下载大型 embedding 权重。
5. 长时间任务恢复：保存每次工具归档和失败原因，重启时标记中断；不自动重放中断的模型任务，避免重复产生模型费用。

## 记忆和压缩的边界

- 完整原始历史从不因压缩被删除。
- 近期完整问答最多四轮；历史窗口超过预算时，将较早轮次移入摘要，至少保留最新一轮完整问答。
- 早期摘要最多 1,000 字符，是问答关键摘录；不额外调用模型，不承诺保留全部历史细节。
- 本轮工具消息不做分层压缩；总输入超出预算时明确报错。
- 原始工具结果供用户在审计界面分页查看，不作为模型回取工具。
- 不从摘要中的数字直接完成财务计算；必须读当轮原始证据。
- as_of 收紧时，较晚资料与相应会话轮次不进入该次研究。
- 金额单位、累计/单季度、合并/母公司以及重述仍需要语义核对。引用存在不等于结论必然正确。

## 评测口径

eval/verified_facts.jsonl 是 20 道根据原文摘录核对的数值/计算参考；覆盖十家公司，但题目很少，尤其留出公司部分只有五题。
eval/tasks_100.jsonl 是 100 道中文任务草稿，按公司划分开发与留出集合。它们覆盖事实、跨期比较、现金流、期间可比性和资料不存在。草稿标明答案仍需审核。

无密钥时只测证据页 Recall@5。不能将这个指标写成模型答案准确率。
rag 模式调用一次固定历史模型，agent 模式运行实际 MCP Agent；两者都会保存答案、用量、耗时和待人工审核状态。
数值出现与参考页码命中属于诊断信号，不代表完整财务分析正确。

## 推荐展示路径

1. 德赛电池 2024 年营收和归母净利润 → 读取第 7 页 → 计算同比 → 引用。
2. 追问“那经营现金流呢” → 观察本会话公司状态保留。
3. 累积多轮问答 → 观察“运行过程”中的近期轮数和早期摘要；重启后续接本会话。
4. 开启新会话 → 确认不会带入另一会话的历史；工具原始结果仍可从运行记录回查。
5. 将 as_of 设为 2025-04-01，再查询 2025 年 4 月披露的年报，观察严格日期过滤。
